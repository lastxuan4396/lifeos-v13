# LifeOS v1.3 Daily Engine

一个本地运行的单页工具，按你给的 PLAYBOOK v1.3 设计：

- 单入口：`DL-30`
- 自动输出：`A/B/C/D`
- 红灯逻辑：`RUIN(S/T/P) -> 默认防线`
- 周趋势：`Scoreboard-5 v1.3` 自动统计（近 7 天）

## 1) 直接打开

在 Finder 里双击 `index.html` 即可使用。

## 2) 推荐本地服务（可选）

```bash
cd /path/to/lifeos-v13
python3 -m http.server 5193
```

然后访问：

- http://localhost:5193

## 3) 使用流程（每天 30 秒）

1. 填 `DL-30` 必填项（行为、结果、昨日 B 是否执行、RUIN；明日意图可空）。昨日 B 需要手动选择；没有可参考的 B 时可选择对应选项，Zero-Day 也一样。
2. 点 `生成 A/B/C/D 并保存`
3. 只执行输出里的 `B`
4. 一周后看 `Scoreboard-5 v1.3`

可选运动和产出指标留空时按未知处理，不会仅因为缺失就判断运动不足或注意力泄漏。
周看板中，睡眠至少 5 天达到 7 小时、训练累计至少 150 分钟、深度工作累计至少 300 分钟或输出至少 800 字时，分别显示达成。未达阈值且相关数据未覆盖近 7 天时显示“数据不足”；周复盘可手动选择或使用一键带入。
周复盘可依据近 7 天记录生成一份可编辑的实验草案；已有实验内容需要确认才会被替换。

## 4) 数据存储

- 存在浏览器 `localStorage`
- Key: `lifeos_v13_entries`
- 每日记录、周复盘和 System Patch 的未提交内容会分别保存在当前浏览器，刷新后恢复；成功保存对应记录后清除草稿。
- 浏览器按网址隔离本地数据。本地预览与原线上地址的数据不会自动互通；迁移请使用“数据与迁移”中的 JSON 备份。
- 导入前会校验备份并显示覆盖前后的记录数量。导入会替换每日、周复盘、Patch 和 Apple 同步数据；建议先导出当前 JSON。未提交草稿和 GitHub 同步配置不包含在备份中。

说明：同一天重复提交时会先显示原记录并询问是否覆盖（避免重复计数）。
要修改已有记录，选择对应日期后点击“载入所选日期的记录”；载入会先询问是否替换当前未提交草稿，修改后再保存。
最近记录默认显示 12 条，可分批展开并直接载入较早记录；输出区会标明其依据的记录日期。

## 离线使用

通过 HTTPS 或 localhost 联网打开一次，等页面显示“离线页面已准备好”后，浏览器可缓存网页本身；之后断网仍可重新打开并保存记录。Gist 同步需要网络，清除浏览器站点数据也会清除本地记录和离线缓存。直接双击 `index.html` 时不能保证离线重新加载。

发布新版本时需同时更新 `sw.js` 的缓存版本号和 `SHELL_MARKER`，以及 `index.html`、`app.js`、`styles.css` 顶部对应的版本标记；标记不一致时离线版本不会安装。新版本准备好后，页面会提示保存内容并更新。较早版本首次切换仍需先关闭所有 LifeOS 标签页再重新打开。

## 5) Zero-Day

如果当天很忙，只填“行为 + 结果”，点 `Zero-Day 一键记录` 也算不断更。

## 6) 数据桥（V2）

已支持设备数据自动回填（URL 参数注入）：

- 睡眠/训练/步数/卡路里/距离
- 软件使用总分钟、手机分钟、电脑分钟、头号应用

若打开设备数据链接时存在未提交草稿，页面会先恢复草稿，并保留链接中的设备数据。保存草稿后点“继续处理设备数据”，或确认放弃草稿后继续；离开该链接前请先处理设备数据。

Mac 一键采集当天应用用时并打开网页：

```bash
python3 scripts/macos_usage_bridge.py --open
```

完整说明见：

- `docs/LifeOS_Data_Bridge_v2.md`

## 7) 多端云同步

网页内置 `多端云同步（GitHub Gist）`：

1. 填 GitHub token（Gists 读写）
2. 点 `初始化云仓`
3. 点 `同步现在（先拉后推）`
4. 可选：勾选 `每次保存后自动同步`

同步会合并不同日期的记录；同一天的记录按保存时间选择较新版本。不同设备同时修改同一天时，请先在一台设备同步完成，再在另一台同步，避免并发覆盖；重要数据建议定期导出 JSON。同步令牌保存在本机浏览器中，请只在可信设备上使用。
