# LifeOS v1.3 Daily Engine

一个本地运行的单页工具，按你给的 PLAYBOOK v1.3 设计：

- 单入口：`DL-30`
- 自动输出：`A/B/C/D`
- 红灯逻辑：`RUIN(S/T/P) -> 默认防线`
- 周趋势：`Scoreboard-5 v1.3` 自动统计（近 7 天）

## 1) 直接打开

在 Finder 里双击 `index.html` 即可使用。

## 2) 推荐本地服务（可选）

```bash
cd /path/to/lifeos-v13
python3 -m http.server 5193
```

然后访问：

- http://localhost:5193

## 3) 使用流程（每天 30 秒）

1. 填 `DL-30` 必填项（行为、结果、昨日 B 是否执行、RUIN；明日意图可空）。昨日 B 需要手动选择；没有可参考的 B 时可选择对应选项，Zero-Day 也一样。
2. 点 `生成 A/B/C/D 并保存`
3. 只执行输出里的 `B`
4. 一周后看 `Scoreboard-5 v1.3`

保存按钮位于必填项之后；如需填写可选方向或指标，请先展开下方对应项目，再保存。可选指标展开区底部也有保存按钮。

若首页显示“今天要做的 B”，完成后可点“已完成，填写记录”，一键带入行为并选择 B 已执行；结果仍需按实际情况填写，随后保存。如果今天已有记录，首页提供载入并编辑入口，以保留记录中的其他内容。
快捷填写会保留 B 的锚点和首个行动，避免目标只写在锚点时丢失上下文。
首页顶部可直接跳转到每日填写区或展开记录与备份入口，跳转不会清空表单。

Quick Mode 默认突出 B 并收起完整 A/B/C/D；点击“查看完整 A/B/C/D”可展开，也可直接复制。记录、复盘和数据工具可通过“查看记录、复盘与数据”展开；Full Mode 默认展开。周复盘和 Patch 草稿状态仍会显示在入口上。

红灯或睡眠预警记录的防线会显示在 B 旁边；第二天回看或复制行动时也会一起带上。旧记录如果无法识别防线，复制内容会保留查看完整输出的提示。

可选运动和产出指标留空时按未知处理，不会仅因为缺失就判断运动不足或注意力泄漏。
周看板中，睡眠至少 5 天达到 7 小时、训练累计至少 150 分钟、深度工作累计至少 300 分钟或输出至少 800 字时，分别显示达成。未达阈值且相关数据未覆盖近 7 天时显示“数据不足”；周复盘可手动选择或使用一键带入。
周复盘可按填写的连续 7 天周期带入，也可带入今天及之前 6 天的数据。按周期带入接受 `YYYY-MM-DD ~ YYYY-MM-DD`（可带 `Week of` 前缀）；页面会显示具体日期，若已填写的指标将被替换，会先询问。
周复盘可用“上一周 / 下一周”切换有效日期范围。切换只更改周期，不自动替换现有表单或结果；可核对后载入该周期记录或重新带入指标。
周复盘会识别日期范围相同的不同写法；保存前会提示要覆盖的已有记录。如果同一范围已有多份记录，可从已保存周期列表选择，其他记录会保留。
周复盘可依据所填复盘周期或近 7 天记录生成可编辑的实验草案，提示中会显示参考日期；已有实验内容需要确认才会被替换。
周复盘或 Patch 的输入更改后，页面会提示先前结果可能不再匹配；复制旧结果前会确认。
月度 Playbook 按记录日期统计每日记录，按周期结束日归类周复盘、按开始日归类 Patch；周复盘或 Patch 的日期无法识别时，按保存月份归类。跨月周复盘归入结束日所在月；动作排行反映记录出现次数。
生成后如果月份或已保存记录发生变化，页面会提示重新生成，复制旧结果前会确认。

## 4) 数据存储

- 存在浏览器 `localStorage`
- Key: `lifeos_v13_entries`
- 每日记录、周复盘和 System Patch 的未提交内容会分别保存在当前浏览器，刷新后恢复；成功保存对应记录后清除草稿。
- 新建 System Patch 时会保留已有 Patch 记录；受浏览器本地存储容量限制，建议定期导出 JSON 备份。
- 在 System Patch 的“已保存的 Patch”中可以载入历史记录；载入前会确认是否替换未提交草稿，重新生成会新增记录，不覆盖原记录。
- 周复盘列表会逐条显示同周期的记录；选择并保存其中一条时，其他记录会保留。
- 周复盘保留草稿时，可勾选“选择时只指定保存目标”后选择同周期记录，再确认保存，不必载入并替换草稿。
- 云同步遇到同周期多份周复盘时保留各份记录；如果不同设备分别修改过，可能同时保留不同版本，需要手动核对。
- 同周期两端各有一份内容不同时，只有保存时间有效且不同时才选择较新版本；时间相同或无法判断时保留两份供核对。
- 云同步会保留 Patch 的不同内容及重复记录数量，不会仅因日期、改动或时间戳相同而合并。
- Dojo 的场景、目标和约束也会在本机保留，刷新后可重新生成脚本；多标签页修改时会提示冲突，也可确认后清除训练输入。
- 每日草稿无法保存时会显示失败提示；即使记录视图刷新，结果区仍会提醒当前表单有未提交内容。
- 同一浏览器的多个标签页同时编辑每日、周复盘或 Patch 草稿时，网页会提示冲突；可选择保留当前页或载入另一份草稿。
- 其他标签页更改每日记录后，当前页的历史列表、周看板和今日行动会刷新；已经显示的结果可能过期，页面会提示重新载入对应记录。
- 结果可能过期时，单独复制 A/B/C/D 前会确认；复制给 LifeOS 时会使用当前表单，省略可能过期的结果。
- 复制给 LifeOS 时，只有表单与结果对应的已保存记录一致，才会附带 A/B/C/D；表单为空、日期或内容不一致时不会附带旧结果。
- 浏览器按网址隔离本地数据。本地预览与原线上地址的数据不会自动互通；迁移请使用“数据与迁移”中的 JSON 备份。
- JSON 备份包含已保存的每日、周复盘、Patch 草稿及 Dojo 输入，不包含 GitHub 同步配置；Gist 同步不上传草稿。导入默认保留本机草稿，可选择恢复备份中的草稿。旧备份不含草稿或 Dojo 输入时，对应本机内容不变。
- 选择备份后可预览备份时间、记录数量与草稿恢复方式；导入前会再次校验并显示覆盖前后的记录数量。旧备份没有有效时间时显示未知。导入会替换每日、周复盘、Patch 和 Apple 同步数据；建议先导出当前 JSON。
- 导入预览会比较当前记录与备份，提示本机独有或不同的内容；确认覆盖期间如本机记录或将被恢复的草稿发生变化，导入会停止。
- 导出 JSON 时会按当前导入规则校验记录；若未通过，可选择导出需修复的数据保留文件，网页不会将其称为可直接恢复的备份。
- 如果本地记录或设备同步信息无法读取，页面会暂停相关保存、常规导出和同步，并提供不含同步令牌的原始数据下载；该文件不能直接作为常规备份导入。

说明：同一天重复提交时会先显示原记录并询问是否覆盖（避免重复计数）。
要修改已有记录，选择对应日期后点击“载入所选日期的记录”；载入会先询问是否替换当前未提交草稿，修改后再保存。手动切换日期会清除“昨日 B 执行”的选择，其他表单内容保留并需要核对。
即使草稿因浏览器存储故障尚未写入，载入旧记录或重新处理设备数据前也会提示确认，取消可保留当前表单。
最近记录默认显示 12 条，可分批展开并直接载入较早记录；输出区会标明其依据的记录日期。
最近记录支持按日期、行为、结果、明日意图、生成的 B 行动和头号应用搜索，可用空格组合多个关键词。

## 离线使用

通过 HTTPS 或 localhost 联网打开一次，等页面显示“离线页面已准备好”后，浏览器可缓存网页本身；之后断网仍可重新打开并保存记录。Gist 同步需要网络，清除浏览器站点数据也会清除本地记录和离线缓存。直接双击 `index.html` 时不能保证离线重新加载。

发布新版本时更新 `sw.js` 的缓存版本号、`SHELL_MARKER` 和版本化资源文件名，以及 `index.html`、`app.js`、`styles.css` 的版本标记；将脚本与样式分别复制成新的 `app-vN.js`、`styles-vN.css`，并更新 `index.html` 的引用。保留旧版资源文件，供仍缓存旧页面的浏览器使用。标记不一致时离线版本不会安装。新版本准备好后，页面会提示保存内容并更新。较早版本首次切换仍需先关闭所有 LifeOS 标签页再重新打开。
点击更新时，如果草稿保存失败、无法读取或与其他标签页冲突，页面会先阻止刷新，直到草稿问题处理完毕。

## 5) Zero-Day

如果当天很忙，填写行为、结果并选择昨日 B 的情况；如进入红灯，还需选择红灯码。点 `Zero-Day 一键记录` 也算不断更。
如果已经填写明日意图，Zero-Day 会一并保存；留空时仍使用默认行动。
普通保存和 Zero-Day 都会检查已填写的可选指标；如果有无效项目藏在折叠区域，会自动展开供修改。

## 6) 数据桥（V2）

已支持设备数据自动回填（URL 参数注入）：

- 睡眠/训练/步数/卡路里/距离
- 软件使用总分钟、手机分钟、电脑分钟、头号应用

设备数据回填后会自动保存为草稿，仍需核对并保存记录。没有未提交草稿时，如果链接日期已有记录，页面会载入原记录并仅把设备数据补入空白项目。若已有未提交草稿，页面会先恢复草稿，并保留链接中的设备数据；同一日期可选择合并到草稿的空白项目，已填写的项目保持不变。若设备数值与表单不同，网页会列出两边的值供核对，确认后才处理链接。不同日期请先保存草稿，再点“继续处理设备数据”。离开该链接前请先处理设备数据。

Mac 一键采集当天应用用时并打开网页：

```bash
python3 scripts/macos_usage_bridge.py --open
```

完整说明见：

- `docs/LifeOS_Data_Bridge_v2.md`

## 7) 多端云同步

网页内置 `多端云同步（GitHub Gist）`：

1. 填 GitHub token（Fine-grained token 的账户权限中将 Gists 设为读写；[GitHub 官方说明](https://docs.github.com/en/rest/gists/gists#create-a-gist)）
2. 点 `初始化云仓`
3. 点 `同步现在（先拉后推）`
4. 可选：勾选 `每次保存后自动同步`

初始化云仓时，创建请求完成前按钮会暂时不可用；已有 Gist ID 时，创建新的云仓前会先确认，原云仓仍保留。
如果云仓创建成功但浏览器未能保存配置，页面会保留并显示新 Gist ID；先记下 ID，再处理浏览器存储问题并重新保存配置。

同步会合并不同日期的记录；同一天的记录按保存时间选择较新版本。上传期间如果本地数据再次改变，网页会提示重新同步。支持 Web Locks 的浏览器会让同一网站的多个标签页轮流同步；不支持时请避免同时同步。不同设备之间仍请先在一台设备同步完成，再在另一台同步，避免并发覆盖；重要数据建议定期导出 JSON。同步令牌保存在本机浏览器中，请只在可信设备上使用。
同一天两端内容不同、但保存时间相同或无法判断时，自动同步会停止且不会覆盖记录；先在各设备导出备份，再在要保留版本的设备上手动同步，核对摘要并确认是否用本机记录覆盖云端。
页面顶部会显示本次打开后的同步进度和结果；本机数据变化后会提示尚未确认同步。刷新后只显示已配置状态，不能把它当作刚刚同步成功的证明。
可在同步设置中清除本机保存的 Token、Gist ID 和自动同步设置；云仓和本地记录会保留，已经开始的请求可能仍会完成。
其他标签页更改或清除同步配置时，本页需先载入最新配置，防止旧表单重新写回旧 Token。
同步期间如果更换云仓或 Token，旧云仓的结果不会显示为新配置同步成功；请按页面提示用当前设置重新同步。
